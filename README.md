# 과제 08: 최소 비용 신장 트리 알고리즘 비교

## 1. 실험 결과

| 구분 | 그래프 | 표현 + 알고리즘 | 간선 수 | MST 간선 수 | MST 비용 | 메모리 | 실행시간 |
|---|---|---|---:|---:|---:|---:|---:|
| Case 1 | 희소 | 인접 리스트 + Kruskal | 100 | 49 | 1462 | 5,788 Bytes | 0.0087 ms |
| Case 2 | 밀집 | 인접 리스트 + Kruskal | 600 | 49 | 271 | 27,788 Bytes | 0.0587 ms |
| Case 3 | 희소 | 인접 행렬 + Prim | 100 | 49 | 1462 | 11,188 Bytes | 0.0067 ms |
| Case 4 | 밀집 | 인접 행렬 + Prim | 600 | 49 | 271 | 11,188 Bytes | 0.0073 ms |

실행시간은 MST 계산을 20,000번 반복한 평균입니다. 같은 그래프에서 Kruskal과 Prim의 MST 비용은 같았습니다.

## 2. 결과 분석

**희소 그래프와 밀집 그래프의 차이**
간선이 100개에서 600개로 6배 늘 때, Kruskal은 실행시간이 약 6.7배 늘었지만 Prim은 약 1.1배만 늘었습니다. Kruskal은 모든 간선을 정렬해야 해서 간선 수의 영향을 크게 받고, Prim은 정점 50개 × 50개를 훑기 때문에 간선 수의 영향을 거의 받지 않습니다.

**인접 리스트와 인접 행렬의 메모리 차이**
인접 행렬은 간선 수와 상관없이 50×50 크기라서 11,188 Bytes로 같았습니다. 인접 리스트는 간선 수에 따라 커져서, 희소 그래프에서는 행렬의 약 절반(5,788 Bytes)이었지만 밀집 그래프에서는 약 2.5배(27,788 Bytes)였습니다.

**Kruskal과 Prim의 실행 특성**
Kruskal은 간선 중심이라 간선이 많을수록 느려지고, Prim은 정점 중심이라 간선이 많아도 거의 느려지지 않습니다. 희소 그래프에서는 비슷했지만(0.0087 ms vs 0.0067 ms), 밀집 그래프에서는 Prim이 약 8배 빨랐습니다.

**그래프 밀도의 영향**
밀도가 높아지면 인접 리스트 + Kruskal은 메모리와 시간이 모두 크게 늘고, 인접 행렬 + Prim은 거의 변하지 않았습니다.

## 3. 결론

간선이 적은 희소 그래프에서는 인접 리스트 + Kruskal이 메모리를 아낄 수 있어 적합하고, 간선이 많은 밀집 그래프에서는 인접 행렬 + Prim이 메모리와 속도 모두 유리했습니다. 정점이 50개뿐이라 시간이 매우 짧으므로, 숫자 자체보다 Case 사이의 비율을 중심으로 해석했습니다.
